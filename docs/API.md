# API reference

The full machine-readable schema (request and response models) is in [`openapi.json`](openapi.json),
generated by `uv run python -m app.cli openapi`. In development the interactive docs are served at
<http://localhost:8000/docs> (disabled in production).

## Conventions

* All `/v1` routes require an authenticated session cookie except `GET /v1/auth/csrf`, registration, the two
  login routes, email verification and password-reset routes. There is **no anonymous document processing**.
* State-changing requests must send `X-CSRF-Token` equal to the `nb_csrf` cookie (bound to the session).
* Errors: `{"detail": "<message>"}` or `{"detail": {"code": "...", "message": "...", "items": [...]}}`.
  Validation errors never echo submitted values.
* Another user's resource returns **404**, so IDs are not confirmed to exist.
* Decisions use optimistic concurrency: send the `version_id` and `row_version` you reviewed; a stale value
  returns **409**.
* Progress: `GET /v1/applications/{id}/events/stream` (SSE; events `progress` with `id:` = event ID, and
  `status`; resumable with `Last-Event-ID` or `?after=`) and the polling fallback `GET .../events?after=N`.
  Both use the session cookie; no secrets or raw identifiers appear in URLs.

application. Processing starts only through submission and the job workflow.
